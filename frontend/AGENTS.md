# frontend/AGENTS.md

React 19 + TypeScript PWA built with Vite. Read the root `AGENTS.md` first.
Full detail: `docs/architecture/frontend.md`.

## Layout

```
frontend/src/
|-- main.tsx
|-- app/             # App, router, providers, queryClient, tab-bar layout
|-- api/             # client.ts (openapi-fetch), schema.gen.ts (generated), csrf.ts, errors.ts
|-- features/<name>/ # api.ts (query/mutation hooks), routes/, components/, index.ts (public API)
|-- shared/ui/       # design system components (Screen, Button, TextField, Sheet, ...)
|-- shared/motion/   # spring presets; the only import point for animation
|-- shared/lib/
|-- pwa/             # service worker registration, install card, iOS guide, update banner
|-- i18n/            # ro.json (default), en.json, setup
|-- styles/          # tokens.css (the only place the look is defined), global.css
|-- design/          # /design page (development only)
`-- test/            # render helpers, API mock helpers, fixtures
```

## Rules (enforced by ESLint, Stylelint and tsc in `make check`)

- Features import each other only through `@/features/<name>` (their `index.ts`).
- No `fetch` outside `src/api/`. Components call hooks from `features/<name>/api.ts`, which use
  `call(api.GET(...))` from `@/api`.
- `src/api/schema.gen.ts` is generated by `make schema`. Never edit it.
- Every user-visible string goes through `t()`; add keys to both `ro.json` and `en.json`.
- Server state lives in TanStack Query. Client-only state that outlives a screen goes in Zustand
  (added with the upload manager). No other state libraries.

## Design system (read `docs/design-system.md` before any UI work)

- The look is fixed by the Crew Challenges design system; follow it exactly. Do not invent styles.
- Writing: one title per screen, no taglines, no small labels above titles, no italic or colored
  words in titles, sentence case, buttons say what happens.
- Colors, spacing, type, radii, shadows, sizes and durations come only from
  `src/styles/tokens.css` (semantic tokens, never `--palette-*`).
- Screens are built from `src/shared/ui` components (`Screen`, `Button`, `TextField`, `Card`,
  `List`/`ListRow`, `StatusPill`, `Avatar`, `Sheet`, `Banner`, `Toast`, ...). No raw `<button>`,
  `<input>`, `<textarea>`, `<select>` or `<dialog>` in features. Need something new? Add it to
  `shared/ui` with all its states, document it in `docs/design-system.md` and show it on
  `/design` first.
- Icons come from `Icon` (Lucide shapes). Add new ones there.
- Animation only through `@/shared/motion` presets (`snappy`, `bouncy`, `gentle`). No trees,
  confetti or illustrations in v1.
- No inline `style`, no hex/rgb colors, no raw px for spacing or font sizes outside tokens.
- Every screen has loading, empty and error states; touch targets >= `--tap-min` (44px);
  layouts use `Screen` (safe areas, `100dvh`, tab bar space).
- Show errors with `errorMessage(t, error)`; dates in the crew's time zone with `formatDateTime`.

## PWA

- `vite-plugin-pwa` with `registerType: 'prompt'`; show the update banner, never reload silently.
- Manifest colors in `vite.config.ts` mirror the tokens; icons come from `scripts/make_icons.py`.
- `src/pwa` follows the shared-code rules: it must not import features or the app shell.
- The service worker never caches `/api`, `/admin`, presigned URLs, or uploads.
- Test install on a real iPhone and Android phone before finishing any PWA change (`make preview`).

## Tests

- Vitest + Testing Library: `renderRoutes()` / `renderScreen()` from `src/test/render.tsx`, mock the
  API with `vi.spyOn(api, "GET")` + `ok()` / `fail()`. Never mock `fetch`. Tests read English text.
- Playwright (`make e2e`) runs against the real backend and the demo crew.
